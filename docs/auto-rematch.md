# 自动续场修正版

## 使用

管理应用、系统悬浮窗和游戏顶部菜单均有独立“自动下一局”开关，使用同一持久配置。仍需开启无人值守，模型自检时不生效。更新后完全重启游戏。

截图流程包含最终排名、任务收益、段位进度；本版等待原生动画结束，使用结算页当前绑定的确认事件，出现“再来一场”后走原生确认窗。不固定等待30秒，不伪造匹配请求。

## 修复与证据

- 将续场异常与原有出牌隔离：旧版续场适配异常会提前返回，跳过无人值守执行。本版同帧恢复原有处理。
- 增加未加载全局保护，读取已加载UI类，避免外部惰性全局查找异常波及打牌。
- 已显示且带有效终局结果的结算页可恢复接管，不再只依赖提前捕获OnShow。
- 已识别结算子页使用游戏自身下一步事件；收益翻页保留实际listener与分页去重。
- 系统悬浮窗、游戏顶部菜单、管理页共用自动续场配置，可运行中撤销。

以上代码缺陷有模拟回归复现；未取得设备模块私有日志，不能声称已证明用户实机故障的唯一根因。APK目标Lua加密，方法与字段依据已有运行时明文转储。

## 验证

```sh
lua5.1 tools/tests/test_auto_rematch.lua
lua5.1 tools/tests/test_auto_discard.lua
lua5.1 tools/tests/test_emoji_compat.lua
```

24条续场、63条自动操作、10条表情回归；仓库构建使用原有工作流。仍需实机确认整场结算、任务与段位页面、重新匹配和新场无人值守。

## 限制

普通段位场 category=2、mode=1/2/11/12；未知奖励弹窗（UI_GetReward）、错误窗暂停处理。手动取消后本场不重试。按钮调用成功仅表示客户端执行了回调，未表示服务器确认匹配。日志组件assistant.rematch记录固定原因码。
